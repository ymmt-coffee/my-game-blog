## 目的

その月曜から日曜までに発売されるPCゲームと、原則20%以上のセール対象から合計5本を選び、公式情報に基づく「新作・セール5選」の安全な下書きを作れるようにしてください。

- Steam・開発元・販売元の公式情報を一次情報とする
- SteamDB等は候補発見や価格履歴の補助に限定し、最終根拠にしない
- 対象期間、発売日、価格、割引率、日本語対応、URLを追跡可能にする
- 未プレイ作品であり、レビューではないことを明記する
- AIが体験、感想、人気、評価、対応言語を捏造しない
- 日曜24時までの私感入力欄を用意する
- 私感がなくても、ユーザーが承認すれば公開可能にする
- 同じ週や同じ作品の下書き・公開を重複させない
- 月曜6時の処理を安全に設計する
- 7時30分と20時向けのSNS素材はローカル生成までとし、実SNS投稿は実装しない

## 実装前に提案し、ユーザー判断を求める事項

現物調査後、推奨案と選択肢に分けて報告してください。決定前に本実装や外部設定を行わないでください。

### 1. 候補収集方法

- SteamまたはValveの公式手段
- 開発元・販売元の公式ページや発表
- 検索エンジンや第三者サービスを候補発見だけに使う方法
- 手動で候補URLを渡し、自動処理は検証以降だけを担当する方法

取得可能性、利用条件、安定性、費用、レート制限、保守性を比較してください。

### 2. 5本の内訳

新作とセールの合計5本という方針は確定していますが、比率は未決定です。

- 固定比率
- 最低枠だけ決める
- 週ごとの候補品質で変える
- 条件を満たす作品が5本未満の場合、件数を減らすか公開を止めるか

架空作品や条件未達作品で5枠を埋めないでください。

### 3. 地域、通貨、価格、割引

- 日本地域・日本円を基準にするか
- 税込表示と取得時刻
- 無料作品、バンドル、体験版、早期アクセスの扱い
- 公開前に価格や割引が変わった場合の再確認期限
- `20%以上`を現在価格と通常価格からどう判定するか

### 4. 日本語対応

ストア表記を基準にし、最低限次を区別する案を示してください。

- インターフェイス
- 字幕
- フル音声
- 日本語未対応または不明

公式情報が矛盾・欠落している場合は推測せず、要確認または掲載除外としてください。

### 5. 下書きと私感

- 週ID、slug、記事タイトルの命名規則
- 5作品の表示順
- 公式事実、AI編集部の選定理由、やまもとの私感を構造的に分離する方法
- 私感が空の場合の表示
- 私感欄へAIが文章を補完しない仕組み
- 出典URLと確認日時を公開本文・非公開証跡のどちらへ残すか

### 6. 月曜6時と公開承認

現在の公開仕様は記事ごとの明示承認を必須とします。一方、Phase 5計画には月曜6時公開があります。次を比較し、ユーザー判断を求めてください。

- 推奨初期案: 月曜6時に検証済み下書きとプレビューを作り、実公開は従来どおり明示承認後
- 日曜中に記事単位の予約承認を行い、月曜6時にその承認済み内容だけを公開
- 完全自動公開。ただし安全性、誤価格、発売延期、公開事故のリスクが高いため、十分な実績と別承認なしに採用しない

通常pushやscheduleを`publish:`承認として扱わず、既存のPhase 3通知条件を後退させないでください。

### 7. 実行場所と時刻

- GitHub Actions schedule
- Windowsタスクスケジューラ
- 手動実行から開始
- 日曜24時を月曜00:00として扱うこと
- PC停止・スリープ、Actions遅延、夏時間の影響を避けてAsia/Tokyoで扱う方法
- 重複実行ロック、再試行、実行上限

### 8. AI利用範囲

- 公式情報を検証・構造化した後だけGeminiへ渡す
- URL、短い公式要約、構造化事実、選定理由に必要な情報だけを許可する
- ページ全文、Cookie、個人情報、別記事、Obsidian全体を送らない
- AI出力を事実の根拠にしない
- AIが私感、プレイ経験、レビュー、Steam評価、話題性を捏造しない

実在記事を最初のAIテストに使わず、架空の構造化候補でfake・stubテストを先に行ってください。

### 9. Discord通知

推奨案:

- 候補不足、公式確認不能、価格変動、発売延期、重複、下書き検証失敗は`要確認`
- API・ネットワーク・保存・Actions失敗は`エラー通知`
- 公開成功は既存`公開通知`条件を維持

通知には記事全文、私感、取得ページ全文、認証情報、自由入力、ログ全文を含めず、週ID、失敗分類、件数、Actions URL、確認手順だけを含めてください。

## 推奨する初期動作

ユーザー判断前は次を推奨してください。

- 外部接続なしのfixture・fake・stubから開始
- 架空の5候補で収集後工程を実装
- 公式情報とAI生成文を分離
- 下書きは一時領域へ生成し、検証後だけ承認済みObsidian保存先へ原子的に配置
- 最初は手動実行またはdry-run
- 月曜6時は自動公開ではなく、検証済み下書き・プレビュー生成まで
- 実SNS投稿は行わず、素材生成だけ
- 実Discord、実AI、実Steam等への通信は個別承認後
- 実記事公開、schedule有効化、commit、pushは別途承認後

## Phase 5固有の自動テスト

最低限、次を外部接続なしで自動テストしてください。

- 週が月・年をまたぐ場合もAsia/Tokyoで月曜〜日曜を正しく計算する
- 日曜24時を翌月曜00:00として扱う
- 同じ週ID、作品ID、正規化URLの重複を拒否する
- 発売日が対象週外の作品を除外する
- 20%未満のセールを除外する
- 日本円以外、地域不明、通常価格不明、割引率不整合を安全に扱う
- 日本語対応のインターフェイス・字幕・音声を混同しない
- 一次情報なし、公式情報矛盾、発売延期、価格変動を要確認にする
- 候補が5本未満でも架空作品や条件未達作品で埋めない
- 選定結果が同じ入力で決定的になる
- 未プレイ記事をレビューや体験談として書かない
- AIが公式事実、URL、価格、日付、日本語対応を変更した場合は拒否する
- 私感が空でも下書きを作れる
- 入力済みの私感をAIが変更しない
- ページ本文、Cookie、token、別記事、個人メモをAI入力へ含めない
- 出典URLと確認日時を追跡できる
- 下書き生成失敗時に既存原稿を変更しない
- 途中ファイルを完成した下書きとして扱わない
- 同じ週の再実行で二重下書き・二重公開しない
- 明示承認なしに`draft: false`、commit、push、実公開を行わない
- schedule、通常push、手動実行を公開承認と誤認しない
- 公開失敗時にSNS素材以外の後続処理を開始しない
- Discord通知へ本文、私感、ファイル名、ログ全文、秘密情報を含めない
- 外部通信、AI、Discord、SNSはfake・stubで確認する
- 既存67テストが引き続き成功する
- Hugo本番相当ビルドが引き続き成功する
- `review-report.md`、PaperMod、`my-blog`、Phase 4バックアップ機能を変更しない

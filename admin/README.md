# ローカルブログ管理画面

Phase Jの最大10件候補試運転と週次収集まで実装済み。PC内だけで記事の作成、編集、公開、予約、カレンダー、アクセス解析、X投稿案に加え、ゲーム情報、出典、価格履歴、候補、判断、収集実行履歴、候補説明を保存できる。週次処理は木曜8:00 JST以降に同じ週で一度だけ実行し、停止中に期限を過ぎた場合は次回起動時に補完する。4Gamer公式RSS、Steam日本向け公開情報、Apify、Geminiは承認済み上限内だけで利用する。

Apify Actorは `fetch_cat/steam-store-games-scraper` を基本情報の補足用として採用した。手動3件試験と管理画面の接続確認に成功している。Steam公開一覧から新作5件・セール5件を発見し、管理画面の「最大10件で候補試運転」を明示的に押した場合だけ、ApifyとSteam日本向け詳細で補足・検証して候補を保存する。正式試運転同士は24時間以内の再実行を停止する。

Steam APIキーとSteam ID64の設定後は、「リリース・セール情報」の「所有ゲームを今すぐ同期」から、次回週次処理を待たずに所有App IDと名称だけを同期できる。2026-08-16に実環境で165件の同期を確認した。キー、Steam ID、プレイ時間、フレンド情報はDBとログへ保存しない。

画面は個人利用向けに説明と装飾を抑え、Noto Sans JP、直線的な枠、小さいボタンを使用する。入力不足は大きな説明枠ではなく件数だけを表示する。

## 起動

デスクトップの「ゲームブログ管理」アイコンを開くと、管理画面を起動して既定ブラウザに表示する。すでに最新版が起動中の場合はブラウザ表示だけを行い、更新前の版が起動中の場合は管理画面のプロセスだけを確認して自動再起動する。

デスクトップアイコンは、UTF-8を正しく扱えるPowerShell 7から起動する。ショートカットには、アプリ更新で変わるWindowsApps内のバージョン別パスではなく、PowerShell 7の共通インストール先を指定する。

手動で起動する場合は、プロジェクトルートで次を実行する。

```powershell
.\admin\start-admin.ps1
```

ブラウザで `http://127.0.0.1:8765/` を開く。終了は起動した画面で `Ctrl+C`。

デスクトップアイコンから起動したPowerShell画面は表示しない。通常は終了操作も不要で、PC終了時に管理画面も終了する。

## 安全性

- 接続先は `127.0.0.1` に固定し、LANやインターネットへ公開しない。
- 同時に複数起動しない。
- 自動再起動は、`127.0.0.1:8765` を使用する管理画面専用プロセスと確認できた場合だけ行う。別アプリは終了しない。
- 状態DBとログはGit管理外の `var/admin/` に保存する。
- 秘密情報や記事本文を状態DBへ保存しない。
- 必須項目の不足は画面に表示するが、執筆途中の下書き保存は妨げない。
- slugは `YYYYMMDD-NNN` の日別連番で自動作成する。
- 記事一覧はタイトル・slugを画面内検索できる。
- 記事一覧は「下書き」「公開済」のタブで切り替える。
- 編集画面上部と記事一覧は、確定保存された最新タイトルを表示する。
- 公開済み記事を保存すると「公開記事の更新下書き」へ移し、投稿完了まで公開中の旧版を維持する。
- 管理原稿と公開用コピーの本文・画像を照合し、「公開済み」「更新あり」「公開差異・要確認」を一覧へ表示する。
- 公開側だけにある記事は「設定・履歴」から管理原稿へコピーできる。既存原稿と公開記事は自動上書き・削除しない。
- 未確定の自動保存があればプレビューと公開前チェックを止め、履歴・復元から確認して手動保存するよう案内する。
- commit前の投稿失敗は公開準備完了のまま残さず更新下書きへ戻し、公開済みタブにも旧公開版がある記事を残す。
- 本文の手動保存と履歴・復元は本文欄の右上へ表示する。下書きでは編集画面下部のアーカイブ欄を表示しない。
- 画像欄は小さいサムネイルと本文貼り付け用Markdownを表示し、ワンクリックでコピーできる。
- アップロード済み画像は「ヘッダー画像に設定」で記事一覧と記事ページの代表画像にできる。解除も同じ場所から行える。
- 本文中の画像をヘッダー画像やサムネイルへ自動転用しない。未設定時は記事カテゴリー別の共通表示を使う。
- 「削除」はファイルを消さない論理削除で、「設定・履歴」の復元欄から戻せる。
- 公開中の記事は通常の「削除」ではなく、slug再入力の確認後に対象の公開コピーだけをcommit・pushする「公開停止」を使う。管理原稿は削除済みに保持する。
- 削除済みから復元した記事が公開コピーと一致する場合は、自動的に公開済みへ戻し、変更のない再投稿を要求しない。
- 移行前原稿の確認入口は記事一覧へ表示しない。
- AI校正は停止中で、公開条件にも含めない。過去の校正データは削除しない。
- 公開は必須項目、画像、リンク、Hugoビルドを検査し、15分以内の最終確認後だけ実行する。
- 公開時は選択記事の正本と公開コピーだけをstageし、混入を検出したら停止する。
- 予約公開は公開前検査と別画面の最終確認を必須とし、確認時の原稿ハッシュと公開日時を固定する。
- 予約後に原稿が変わった場合やGit・Pagesで異常が起きた場合は自動公開せず、公開準備完了へ戻して理由を表示する。
- 管理画面停止中に時刻を過ぎた予約は、次回起動時に処理する。時刻どおりの公開にはPCと管理画面の起動が必要となる。
- アクセス解析は日別・ページ別の集計済みCSVとUmamiの `website_event.csv` を取り込み、個別のセッションID、IPアドレス、Cookie、端末、地域、参照元の生データをSQLiteへ保存しない。
- 公開サイトはUmami Cloudへ接続済みである。API自動取得は行わず、毎月の手動エクスポートと取込で運用する。

依存パッケージはプロジェクトルートの `requirements.txt` から導入する。

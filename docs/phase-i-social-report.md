# Phase I X投稿初期実装報告

作成日: 2026-08-12
更新日: 2026-08-14
状態: Xのローカル手動範囲は完了、X API連携は保留

## 実装した範囲

- 管理画面の「X投稿」から、公開済み記事を選んでX投稿案を作成できる。
- 投稿案には記事タイトル、概要、公開記事URLを使用する。
- 投稿文を編集、保存、クリップボードへコピーできる。
- 人が内容を確認したことを「確認済み」として記録できる。
- 実際にXへ手動投稿した後、任意の投稿URLを記録できる。投稿先はXとして自動記録する。
- 投稿案と状態はlocalhost内のSQLiteへ保存する。

## 安全策

- Xへの通信、ログイン、投稿は行わない。
- 投稿案の作成対象は、管理原稿と公開中の内容が一致する記事に限定する。
- 投稿案作成後に記事が変更された場合は、古い投稿案の確認と手動投稿済み記録を停止する。
- 手動投稿済み記録は外部投稿の承認や自動投稿の予約として扱わない。
- 投稿URLは任意とし、入力時は `http` または `https` のURLだけを受け付ける。
- テストでは外部サービスを呼ばない。

## 操作手順

1. 管理画面の「X投稿」を開く。
2. 公開済み記事を選び、「投稿案を作る」を押す。
3. 必要に応じて文章を直し、「投稿案を保存」を押す。
4. 内容を確認して「内容を確認済みにする」を押す。
5. 「コピー」で投稿文をコピーし、Xへ手動で投稿する。
6. 管理画面へ戻り、任意の投稿URLを入力して「Xへ投稿済みにする」を押す。

## 保留した範囲

当面の投稿先はXだけとする。Blueskyは利用せず、必要性が生じた場合に再検討する。

1. X APIの費用、権限、利用条件の再確認
2. 投稿予約とカレンダー統合
3. 投稿結果の取得
4. 明示承認を維持した自動化

認証情報はGitへ保存しない。外部接続を始める場合は、サービスの料金、API制限、権限、失敗時の扱いを先に確認する。

## 検証項目

- 公開記事からの投稿案作成
- 投稿案の編集、確認済み、手動投稿済みへの状態変更
- 記事変更後の安全停止
- 不正な投稿URLの拒否
- SQLite schema version 7への移行
- 管理画面全回帰テスト

# サイト構成・機能リファクタリング報告

実施日: 2026-08-11

## 目的

Phase AからPhase Fまでに追加した記事管理、公開処理、公開ブログ表示を、現在の挙動と安全策を維持したまま保守しやすい構造へ整理する。

## 実施内容

### 管理画面

- 新規作成、手動保存、自動保存で個別に解釈していた記事入力を `admin/article_input.py` へ集約した。
- 文字列とJSONの真偽値を同じ規則で扱い、クリア状況などの保存経路による差を防いだ。
- 有効な記事カテゴリーはテンプレート定義から取得し、別の固定一覧との重複をなくした。
- 管理画面の実装版を `phase-f-9` に更新し、デスクトップ起動時に旧プロセスが残らないようにした。

### 公開ブログ

- 記事カテゴリーの日本語名を一つの部分テンプレートへ集約した。
- トップページの記事抽出・並び順とLATEST表示を独立した部分テンプレートへ分けた。
- 最新記事判定もトップページと同じ並び順を再利用し、同日公開時の判定差を防いだ。
- 日付と経過時間の表示を一つの部品へまとめ、過剰に細分化されていた部品を削除した。
- 公開CSSへ役割別の区切りを設け、基本、共通ヘッダー、一覧、記事、レスポンシブの境界を明確にした。

## 維持した挙動と安全策

- 記事、画像、公開用コピー、SQLiteのデータ構造は変更していない。
- 原子的保存、履歴、競合停止、記事限定commit・push、公開失敗時の復旧処理は変更していない。
- 既存記事や未追跡記事の本文・画像は変更していない。
- URL、カテゴリー内部値、公開ページ構成、管理画面の操作手順は変更していない。
- PaperMod submoduleは変更していない。

## 検証

- 管理画面、公開処理、バックアップの全回帰テスト
- Hugo本番相当ビルド
- カテゴリー名、トップ記事順、LATEST、記事メタ情報の生成結果
- Git差分、秘密情報、submodule、未追跡記事の非変更確認

この作業ではcommit、push、GitHub Pagesへの公開を行わない。

# Phase C 記事管理 実装報告

実施日: 2026-08-09
状態: 実装完了・ローカル検証済み

## 結論

ローカル管理画面で、下書き記事の新規作成、一覧、編集、画像追加、自動保存、確定保存、履歴確認、復元、アーカイブができるようになった。

記事管理画面は「全体メニュー」「折り畳み可能な記事一覧」「選択した記事の内容」の3層構成とする。記事一覧の開閉状態はブラウザに記憶する。

記事本文と画像は `content/articles/<slug>/` の通常ファイルが正本であり、SQLiteには管理状態と履歴だけを保存する。SQLiteが失われてもMarkdownから記事一覧を再構築できる。

既存Obsidian原稿は移動・コピー・削除していない。管理画面では読み取り専用の移行dry-runだけを提供する。実移行は引き続き未承認である。

## 日常操作

デスクトップの「ゲームブログ管理」アイコンから起動し、左メニューの「記事管理」を開く。

### 新規作成

「新しい記事」からタイトル、slug、カテゴリー、著者を入力する。内部データでは従来との互換性のため `article_type` を維持する。作成時は必ず `draft: true` の下書きになり、公開処理は動かない。

「概要」は記事の短い紹介文である。記事ページ冒頭、検索結果、検索エンジン向け説明、SNS共有時の説明などに使うため、本文の要点を1〜2文で入力する。

### 編集と保存

- 入力から2秒後、遅くとも30秒以内にGit管理外の自動保存領域へ保存する
- 「手動保存」で正本を確定保存する
- 確定保存前の版を `var/admin/history/` に残す
- 保存状態を「未保存」「自動保存中」「自動保存済み」「保存中」「保存済み」「競合・保存停止」で表示する

### 競合

同じ記事を別画面で保存した場合や外部アプリで変更した場合は、後からの上書きを停止する。外部ファイルの内容を確認し、「外部変更を取り込む」を明示実行した場合だけ管理台帳を更新する。

### 復元

履歴や異常終了前の自動保存を編集画面へ「復元候補」として読み込む。正本は直ちに上書きせず、内容を確認して手動保存した場合だけ確定する。

### 画像

PNG、JPEG、GIF、WebP、AVIFを記事ごとの `images/` に追加できる。日本語、空白、記号を含むファイル名は、安全な半角ファイル名へ自動変換する。10MBを超える画像、空ファイル、未対応形式、変換後に同名となる画像は停止する。既存画像の削除と無断上書きは実装していない。

### アーカイブ

記事の状態だけを `archived` にする。Markdownと画像は移動・削除しない。アーカイブから戻すと編集できる。

## データ構造

```text
content/articles/<slug>/
├─ index.md
└─ images/

var/admin/
├─ admin.sqlite3
├─ autosave/<article-id>/
├─ history/<article-id>/
└─ migrations/latest-dry-run.json
```

`content/articles/` はGit管理対象、`var/admin/` はGit管理外である。記事本文や画像をSQLiteへ保存しない。

## SQLite migration

schema version 2として、記事台帳、記事操作履歴、警告・エラーの基礎テーブルを追加した。既存のversion 1 DBは起動時に追加migrationされる。

DBを失った場合は `content/articles/*/index.md` を読み取り専用で走査し、slugから安定した記事IDを再生成する。公開済み状態などを推測せず、再構築記事は安全な下書きとして扱う。

## 既存原稿の移行dry-run

「既存原稿を確認」画面は外部原稿を読み取り専用で走査し、slug、タイトル、画像数、警告を表示する。結果を `var/admin/migrations/latest-dry-run.json` に保存する。

次は行わない。

- `content/articles/` へのコピー
- 元原稿の変更・移動・削除
- Obsidian設定の変更
- 公開側記事の変更

## 安全策

- localhostと許可Host制限を維持
- 更新操作にCSRF確認を必須化
- slugと全パスを許可範囲へ限定
- 一時ファイル、flush、原子的置換で保存
- ファイルハッシュとrevisionの両方で競合検出
- 同名画像を上書きしない
- アーカイブは論理方式で削除しない
- 復元は候補表示を経て手動保存
- SQLiteへ本文、画像、秘密情報を保存しない
- 公開、Git操作、AI、外部サービス接続を実装しない

## テスト

管理画面のPhase B・Cテスト16件で次を確認した。

- localhost限定とHost拒否
- DB version 1から2へのmigration
- 新規記事と通常Markdown
- 自動保存が正本を変更しないこと
- 確定保存と履歴
- stale revisionと外部変更の停止
- 外部変更の明示取り込み
- CSRFなし更新の拒否
- 画像追加と同名上書き拒否
- アーカイブと復元
- 履歴から復元候補を作り、確認後だけ保存できること
- DB消失後のMarkdown再走査
- 既存原稿dry-runがコピーしないこと

全回帰として記事関連25件、バックアップ関連26件、Hugo本番相当ビルドも確認する。

## 保留事項

- 既存原稿の実移行は未承認
- 既存画像の削除・置換は未実装
- 記事種類ごとの入力フォームと厳密な必須項目はPhase D
- 校正、プレビュー、公開はPhase E
- Phase Eまでは管理画面の校正・プレビュー・投稿ボタンを無効表示し、従来のObsidianショートカットを使う
- Obsidian暫定運用はPhase E完了と移行確認まで継続

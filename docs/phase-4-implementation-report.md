## 方針と保留

- 日次はcopyで、ローカル削除をDriveへ伝播しない。古いファイルが残り容量を使う代わりに誤削除へ耐える。
- 日次対象は除外後の`Life_and_Div`全体、月次12世代は`.obsidian`、`30_Projects/01_blog`、`my-blog`、`my-game-blog`に限定した。
- 月次許可リストをrclone自身へ適用した結果は397ファイル・8,751,823 bytes、12世代の現在値換算は105,021,876 bytes。その他の開発ツールは日次には含むが月次へ自動追加しない。
- 新しい月のcopy・検証成功後だけ13個目以降を候補にする。初回実削除はdry-run承認後。
- 暗号化はrclone crypt採用に決定し、パスワードとsaltを設定済み。秘密値は確認・記録せず、保管場所だけをユーザー依頼により記憶した。
- OAuth token、rclone設定、crypt情報はリポジトリ、Obsidian、`.env`、ログ、Discord、artifactへ保存しない。
- `rclone.conf`は専用パスワードで暗号化し、その解除情報をWindows DPAPIのCurrentUserスコープと現在ユーザー限定ACLで保護した。非対話解除とDrive容量の読み取り接続に成功した。
- タスク2件を登録し、初回バックアップの検証成功後に有効化した。日次は毎日02:00、月次は毎月1日03:00。起動後の取りこぼし実行、スリープ解除、バッテリー開始禁止、重複拒否、15分間隔2回再試行、2時間上限を設定した。
- 初回実行ではGoogle Drive通信が途中で失敗したが、完了マーカーを作らず停止した。一方向copyを再実行し、送信済み一致ファイルを再利用して日次・月次とも全体検証へ到達した。
- 月次完了マーカーが日次全体の件数・容量を記録する不備を検出し、月次許可リスト適用後のrclone集計値を使うよう修正した。削除なしの再整合後、月次400ファイル・8,764,111 bytesと完了マーカーの一致を確認した。
- Discord用Actionsはローカルファイルだけ追加し、push・有効化・実送信していない。
- GitHub CLI再認証方式は未決定。通知依頼失敗時は秘密なしの短い状態記録を残す設計とする。

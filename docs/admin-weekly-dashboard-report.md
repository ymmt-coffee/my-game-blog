# 管理画面 週次トップページ実装報告

## 実施日

2026-08-22

## 目的

管理画面を開いた直後に、今週どこまで進み、何が止まり、次に何をすればよいかを確認できるようにする。個人用ツールとして情報量を増やしすぎず、詳しい操作は既存の各画面へ任せる。

## 実装内容

- 月曜日から日曜日までの期間を日本時間で自動計算
- 月曜日から日曜日までの作業目安を週間スケジュールとして表示し、当日を強調
- 木曜日欄から、所有ゲーム同期から候補説明までの週次情報収集を1ボタンで実行。同じ週が処理済みなら「更新済み」と表示
- レビューは日曜日までに対象ゲームを決め、翌週の日曜日までプレイ・執筆し、その次の水曜日に予約公開する流れを表示
- 新作・セールは木曜日に情報収集し、選定・執筆を経て日曜日に公開する流れを表示
- 2本目以降のレビューは余裕がある週だけ追加し、必須予定には含めない
- 公開済み、記事制作、編集中、予約の実数を表示
- 公開数と記事制作数だけ前週値を表示
- 要確認、今日公開、公開準備完了、編集中、候補選定、情報収集、X投稿案の順で次の作業を最大3件表示
- 今週作成・更新・公開・予約した記事と、継続中の記事を最大5件表示
- 新作・セール記事を、情報収集、候補選定、記事制作、公開、X投稿の工程で表示
- プレイ候補、今週購入、プレイ中、評価待ちを、記録がある場合だけ表示
- 予約停止、期限超過、情報収集の部分失敗・失敗を、問題がある場合だけ最上部へ表示

## 集計上の安全策

- トップページの表示だけではSQLiteと記事front matterを読むだけで、保存、記事作成、外部通信、AI実行を行わない。木曜日欄の情報収集は、人がボタンを押した場合だけ既存の承認済み週次処理を実行する。
- 月曜日の切り替えは日付範囲だけを変更し、記事や履歴を削除しない。
- 未完了の記事は翌週も表示対象とし、途中の作業を見失わない。
- 新作・セール候補は、その週に実在する有効候補数を上限として表示する。候補が5件未満でも、存在しない候補を未達として扱わない。
- 進捗率は使用せず、「未着手」「進行中」「要確認」「完了」と実数で表示する。
- アクセス解析値は週途中の制作進捗へ混ぜず、従来どおりアクセス解析画面で扱う。

## 検証

- 週が月曜日から日曜日になること
- 継続中の記事が今週の記事へ表示されること
- 要確認が最優先の次作業になること
- 空データでもトップページが表示できること
- PC幅と390px幅で横方向にはみ出さないこと
- 管理画面の全回帰テスト
- Hugo本番相当ビルド

週間ルーチンと収集ボタンの状態判定は `admin/weekly_routine.py` へ分離し、トップページと情報収集画面が同じ完了・再試行判定を利用する。

実サービスへの送信、記事変更、commit、push、公開は行っていない。

# Phase G 予約とカレンダー実装報告

作成日: 2026-08-11
状態: 実装・検証完了

## 実装内容

- 記事編集画面へ予約日時、予約前チェック、予約解除を追加した。
- 予約前チェック時に画面上の最新内容を、通常の手動保存と同じ履歴・競合検査で確定保存する。
- 予約は「検査結果の表示」と「この日時で予約する」の2段階確認にした。
- 予約確定時の原稿ハッシュとHugo検査済みコピーを固定した。
- 管理画面の起動中は30秒間隔で期限到来を確認し、対象記事だけをcommit・pushする。
- 管理画面停止中に期限を過ぎた予約は、次回起動時に処理する。
- 月・週カレンダーへ記事の予約日時と公開日時を表示した。

## 安全策

- 過去日時は予約できない。
- 確認は15分間、一回だけ有効とする。
- 予約後に原稿ハッシュが変わった場合は公開しない。
- 検査済みコピーが失われた場合は公開しない。
- Git、push、Pages確認の失敗を成功扱いにしない。
- 失敗時は記事を公開準備完了へ戻し、安全な理由を管理画面と操作履歴へ残す。
- SQLiteには本文や画像を保存せず、予約日時、ハッシュ、状態だけを保存する。
- テストでは実際のcommit、push、Pages、外部サービスを呼ばない。

## カレンダーの範囲

現在は記事予約と記事公開だけを表示する。SNS投稿、発売日、セール終了日は、Phase I・L等で各データが実装された後に同じカレンダーへ追加する。

## 運用上の注意

管理画面はクラウド上の常駐サービスではない。指定時刻どおりに公開したい場合はPCと管理画面を起動しておく。停止中に時刻を過ぎても予約は失われず、次回起動時に処理される。

## 検証

- 予約確認、確定、解除
- 月・週カレンダー表示
- 期限到来時の公開処理（外部処理はfake）
- 予約後の原稿不一致による安全停止
- 過去日時の拒否
- 管理画面の全回帰テスト
- Hugo本番相当ビルド

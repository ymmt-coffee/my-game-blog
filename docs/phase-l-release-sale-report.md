# Phase L リリース・セール情報 実装報告

## 実装内容

- 左メニューと画面を「情報収集」と「リリース・セール情報」に分けた。
- 「情報収集」は収集準備、収集実行、最新周期の新作、セール・無料、その他、除外理由を扱う。
- 「情報収集」で候補ごとのSteam日本向け公式情報再確認と、発売日・セール終了日のカレンダー追加・解除を行える。
- 「リリース・セール情報」は週刊記事へ載せる新作を最大5本、セール・無料を最大5本選択する。
- 選択全件の公式再確認に成功した場合だけ、まとめて1本の未完成・未公開下書きを作る。
- カレンダー選択をSQLite schema version 11、週刊記事の掲載候補をschema version 12へ保存した。

## 安全策

- 画面表示だけではSteamやAIへ接続しない。
- 選択した候補の公式再確認が1件でも失敗した場合は記事を作成しない。
- 記事本文、購入、公開、SNS投稿を自動実行しない。
- 日付が不明な予定を推測してカレンダーへ追加しない。
- テストでは外部サービスを呼ばず、固定応答を使用する。

## 確認項目

- 情報収集と週刊記事選定の画面分離
- 情報収集側の候補4区分と最新周期限定
- 新作5本、セール・無料5本の選択上限
- 選択全件の直前再確認付き統合下書き
- 下書きが `draft: true` のままであること
- 発売日・セール終了日の追加・解除
- 既存管理画面の回帰テスト

2026-08-20に管理画面116件、バックアップ31件、公開処理26件のテストが成功し、Hugo本番ビルド25ページも成功した。Hugoの時刻基準を `Asia/Tokyo` へ統一し、日本時間の当日記事が午前9時前のプレビューで未来記事として除外されないことを実記事で確認した。

## 保留事項

- Steam公開情報からセール終了日を取得できない商品では、日付を推測せずボタンを表示しない。
- 統合下書きの作成とプレビュー表示は実候補で確認済み。本文内容と公開操作の最終確認は実運用の記事で行う。

# 記事の校正・プレビュー・公開手順

## 現在の位置づけ

Phase Eの完成後は、通常の記事操作をローカル管理画面で行う。この文書は管理画面の操作手順と、移行前原稿に限る従来経路を示す。

Discord通知は使用しない。

## 管理画面での通常手順

1. デスクトップの「ゲームブログ管理」を開き、記事を選ぶ。
2. 記事を確定保存する。
3. 「プレビュー」で表示を確認する。
4. 「公開前チェック」を押す。
5. 合格画面で対象、公開先、警告、原稿ハッシュを確認し、対象slugを入力して「投稿を実行」を押す。
6. Pages完了画面を確認する。

公開前チェックの承認は15分間、一回だけ有効である。検査後に原稿が変わった場合は再検査する。

## 公開済み記事の更新

公開済み記事を編集している間、自動保存は復元用領域にだけ保存され、公開ページは変わらない。手動保存すると管理用原稿を「公開記事の更新下書き」として保存し、公開中の旧版は維持する。更新下書きが途中のまま残ってもWebへ公開されない。

手動保存されていない自動保存がある場合、プレビューと公開前チェックは停止する。編集画面の案内から「履歴・復元」を開き、自動保存内容を確認して手動保存してから再実行する。commit前に投稿が失敗した場合は、公開準備完了のまま残さず「公開記事の更新下書き」へ戻す。旧公開版がある記事は更新作業中も公開済みタブから確認できる。

修正完了後にプレビュー、公開前チェック、最終確認、投稿を行うと更新版が公開される。手動保存前の内容は履歴へ退避されるため、必要に応じて「履歴・復元」から確認できる。

## 原稿

管理画面の記事は `content/articles/<記事slug>/` のPage Bundleを正本として扱う。移行前の外部テスト原稿は2026-08-09にユーザー承認を得てWindowsのごみ箱へ移動済みで、現在の外部原稿フォルダは空である。

公開用コピーは `blog/content/posts/<記事slug>/` に置く。管理画面は正本と公開用コピーの本文・画像を照合し、一覧へ次の状態を表示する。

- `公開済み`: 正本と公開用コピーが一致している。
- `更新あり`: 公開中の旧版を維持したまま、正本に未公開の修正がある。
- `公開差異・要確認`: 公開済みの記録があるが公開用コピーを確認できない。

公開側だけにある記事は「設定・履歴」の「公開側だけの記事」から管理画面へ取り込む。取り込みは公開記事を変更せず、正本へコピーして `draft: true` にする。同じslugの正本がある場合は停止する。

下書きの「削除」はローカルの論理削除だけを行う。公開中の記事は「公開停止」を選び、確認画面でslugを入力した後、対象の公開用コピーだけをcommit・pushしてサイトから取り下げる。管理原稿は削除せず「設定・履歴」に保持する。公開中の内容と同一の記事を復元した場合は公開済みへ戻るため、変更のない再投稿は不要である。

```text
<記事slug>/
├─ index.md
├─ review-report.md
└─ images/
```

- 公開本文は `index.md`。
- 校正記録は `review-report.md`。公開対象へ含めない。
- 画像は記事ごとの `images/` に置く。
- 執筆中は `draft: true`、公開時だけ明示的に `draft: false` とする。

## 記事種類

- `play_note`: プレイ途中記。`play_time` が必須。
- `weekly_picks`: 新作・セール5選。未プレイ情報記事として表示する。
- `monthly_essay`: 月次レビューエッセイ。

## 校正

管理画面のAI校正は、操作のテンポを優先して現在停止・非表示としている。公開前チェックでも校正結果を必須にしない。過去の校正記録は削除しない。

```powershell
.\tools\publishing\review.ps1 -Article <記事slug> -Gemini
```

校正は本文を自動修正しない。指摘を確認し、採用する内容だけ人が本文へ反映する。APIキーは環境変数からだけ読み、値を表示しない。

## プレビュー

```powershell
.\tools\publishing\preview.ps1 -Article <記事slug>
```

必須項目、画像、内部リンク、秘密情報を検査してからローカルHugoサーバーを起動する。

## 公開

```powershell
.\tools\publishing\publish.ps1 -Article <記事slug> -Approve
```

公開処理はfront matter、画像、リンク、Hugo本番ビルドを検査し、対象記事だけをcommit・pushする。GitHub Pagesの成功と公開URLのHTTP 200を確認する。commitとpushを伴うため、実行前に毎回ユーザー承認を得る。

## 移行前原稿の暫定経路

現在、移行前原稿は存在しない。従来の外部Obsidian経路は使用せず、通常操作は管理画面で行う。

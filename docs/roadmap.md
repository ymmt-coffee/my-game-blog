# ローカル管理画面 再構築ロードマップ

## 現在地

2026-08-09に旧Phase方式を停止し、管理画面中心の計画へ移行した。Hugoブログ、校正、プレビュー、公開、検査、バックアップは維持している。Discordと週次AI調査は保留した。

## Phase A: データ構造と移行設計

- 記事と画像の正本を決める
- 既存記事と外部原稿の移行方法を決める
- 記事状態、予約、履歴のSQLiteスキーマを決める
- 自動保存、復元、アーカイブ方針を決める
- 管理画面から既存公開処理を呼ぶ境界を決める

完了条件: ファイル配置、状態遷移、移行、失敗時の復元方法が文書とテスト案で確定している。

## Phase B: 管理画面の土台

- localhost限定のローカルWebアプリ
- 固定左メニューと画面切替
- 設定・履歴・エラー表示の基礎
- 未実装画面の準備中表示

完了条件: 外部公開されず、起動と終了が簡単で、記事管理画面へ移動できる。

## Phase C: 記事管理

- 記事一覧、新規作成、編集
- 画像追加、並べ替え、説明文
- 自動保存、手動保存、復元
- 状態管理とアーカイブ
- 既存記事の安全な読み込み

完了条件: 管理画面だけで下書きを作成・再編集でき、失敗時に元記事を壊さない。

## Phase D: 記事テンプレート

- プレイ途中記
- 新作・セール5選
- 月次レビューエッセイ
- 必須項目と記事種類別検査

完了条件: 3種類の記事をフォームから正しいMarkdownとして作成できる。

## Phase E: 校正・プレビュー・公開

- AI校正と指摘の採否
- Hugoプレビュー
- 公開前チェック
- 最終確認
- 記事単位のcommit、push、Pages確認

完了条件: ObsidianとDiscordを使わず、管理画面だけで記事公開を完了できる。

## Phase F: ブログデザイン

- 記事一覧と記事ページ
- モバイル表示、読みやすさ、アクセシビリティ
- 広告を後から追加できる限定的な配置場所
- 実記事を使った表示確認

完了条件: 公開ブログのデザインが確定し、広告なしでも不自然な空白を作らない。

ここまでをブログ投稿MVPとする。

## Phase G: 予約とカレンダー

記事画面へ予約を追加した後、月・週カレンダーを実装する。

## Phase H: アクセス解析

外部データ取得、表示、比較、改善提案の順に実装する。

## Phase I: SNS

投稿案、確認、手動投稿、予約、結果取得、自動化の順に実装する。

## Phase J: 共通情報収集

AI編集部とリリース・セール画面が共有する、検証済みゲーム情報の収集基盤を作る。

## Phase K: AI編集部

候補3本、理由、予算、採用・保留・見送り、記事下書き作成を実装する。

## Phase L: リリース・セール情報

候補の絞り込み、公式情報確認、5本選択、記事下書き作成、カレンダー反映を実装する。

## 共通停止条件

秘密情報、記事破損、対象外変更、検査失敗、Hugoビルド失敗、状態不整合、承認不足がある場合は保存または公開を停止する。外部接続、commit、push、公開は個別承認を必要とする。

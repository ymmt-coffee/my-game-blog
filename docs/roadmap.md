## Phase E: 校正・プレビュー・公開

状態: 2026-08-09に実装・ローカル検証完了。詳細は `phase-e-publishing-report.md`。

- AI校正と指摘の採否

- 最終確認

完了条件: ObsidianとDiscordを使わず、管理画面だけで記事公開を完了できる。

確認結果: AI校正の本文非変更、指摘の採否、校正鮮度、Hugoプレビュー、公開前検査、15分有効の最終確認、記事限定Git操作、Pagesと公開URL確認を実装した。テストはfake/stubを使用し、実AI・commit・push・公開は行っていない。

現在の運用調整: slugは日付＋日別連番で自動作成し、記事検索、下書き・公開済タブ、設定・履歴から復元できる論理削除を追加した。移行前原稿の確認入口は記事一覧から外した。AI校正はテンポを優先して停止・非表示とし、公開前検査の必須条件から外している。

公開整合性の調整: 管理原稿を正本、公開側を生成コピーとする安全構造を維持し、本文・画像の一致、未公開更新、公開コピー欠落を管理画面で判定する。公開側だけの記事は自動変更せず、設定・履歴から非破壊で取り込める。

削除と復元の調整: 公開中の記事はslug確認付きの公開停止で対象コピーだけを取り下げ、管理原稿は削除済みに保持する。公開コピーと一致する記事を復元した場合は、変更なしの再投稿を要求せず公開済みへ戻す。

移行前の外部テスト原稿3件は2026-08-09のユーザー承認によりWindowsのごみ箱へ移動済みで、管理画面の記事と公開用記事は保持している。

## Phase L: リリース・セール情報

状態: 2026-08-19に実装完了。「情報収集」に収集実行、最新周期の4区分、除外理由、公式再確認、カレンダー選択を集約した。「リリース・セール情報」は最新周期の有効候補から新作5本、セール・無料5本までを選択し、全件の公式再確認に成功した場合だけ1本の未完成・未公開 `weekly_picks` を作成する。画面表示による外部通信、自動記事作成、自動公開は行わない。選択状態はSQLite schema version 12へ保存する。

## 共通停止条件

秘密情報、記事破損、対象外変更、検査失敗、Hugoビルド失敗、状態不整合、承認不足がある場合は保存または公開を停止する。登録済み媒体、Steam、Apify、Geminiへの週次接続は承認済みの件数・費用・送信情報の範囲だけ定期実行できる。新しい接続先、上限変更、commit、push、公開、購入、SNS投稿は個別承認を必要とする。

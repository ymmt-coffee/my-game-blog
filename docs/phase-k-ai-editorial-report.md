# Phase K AI編集部 実装報告

追補: 判断・購入・プレイ記録の削除と、記事本体を残した記事企画の関連解除を追加した。これにより試し入力を管理画面から安全に取り消せる。

## 実装日と範囲

2026-08-19に、Phase Jの検証済みゲーム候補を、購入・プレイ・記事企画へつなぐローカルAI編集部を実装した。管理画面の「AI編集部」から利用できる。

## 候補3本

最新周期の有効候補だけを対象にし、新作・近日発売とセール・無料配布が存在する場合は1本ずつ含め、残りを総合点順に選ぶ。該当候補がなければ無理に3本へ埋めない。

同じ判断をすぐ繰り返さないよう、プレイ候補・記事候補は4週間、保留は2週間、興味なしは通常の上位候補から除外する。判断履歴と「これから遊ぶゲーム」は画面下部に残す。

推薦文はPhase Jで週1回保存したGemini説明を再利用する。説明がない場合も固定採点と事実情報を表示し、画面を開くたびにAIを呼ばない。価格、所有状態、Steamリンクと総合点を同じ候補欄で確認できる。

## 人が記録する項目

- プレイ候補、記事候補、保留、興味なし
- 購入日、購入価格、任意のメモ
- プレイ中、クリア、中断
- 良かった、普通、合わなかった、未評価
- プレイログ、新作・セール、月刊コラム、記事化せずプレイのみ

月間購入合計は通常10,000円までとする。合計が10,000円を超える場合は例外確認を必須とし、20,000円を超える記録は停止する。カード番号等の決済情報は保存しない。

## 記事下書き

「下書きを作成」を押した場合だけ、既存の記事管理へ通常のMarkdownを作る。状態は下書きで、概要と、プレイログの場合はプレイ時間を未入力にする。このため、利用者が記事管理で完成させるまで公開前検査を通らない。

ゲームと記事IDの対応だけをSQLiteへ記録する。AI編集部は記事本文を書かず、既存記事を変更せず、commit、push、公開、SNS投稿を行わない。「記事化せずプレイのみ」を選んだ状態では下書きを作らない。

## データと安全策

SQLite schema version 10として、購入、プレイ評価、ゲームと記事下書きの対応を追加した。既存のゲーム情報と外部サービスの認証情報は分離したままで、秘密情報を追加保存しない。外部APIを呼ばないfakeデータのテストで、候補混成、予算上限、記録、未公開下書き、記事化しない選択を確認した。

## 保留事項

- 実際の候補データでの画面操作と見た目の確認
- 大幅値下げや正式リリース等を検出して、判断抑制期間中でも再提案する例外処理
- 4週間後の候補品質・興味なし率・予算運用の見直し
- Phase Lの新作5本、セール5本、公式情報再確認、選択予定のカレンダー連携

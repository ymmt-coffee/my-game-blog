# Phase J 共通ゲーム情報基盤 実装報告

## 実装日と範囲

2026-08-15から16日に、Phase JのSQLite共通基盤、暗号化バックアップへDBを安全に含める準備、Apify固定3件接続確認、最大10件の候補試運転、4Gamer公式RSS、週次収集、Gemini候補説明、Steam公式APIによる所有ゲーム同期を実装した。ウィッシュリスト同期と記事下書き作成はまだ行っていない。

## 保存できる情報

- Steam App IDを主キーにしたゲーム情報
- 国内販売、日本語対応、シングルプレイ、早期アクセス、基本無料
- Steamレビュー、所有・ウィッシュリスト状態と同期日時
- 情報源の記事タイトル、媒体名、URL、日時、短い要約、候補理由
- 日本円の通常価格、現在価格、割引率、セール終了、観測日時
- 週次候補の種類、状態、100点の内訳、理由、除外理由
- プレイ候補、記事候補、保留、興味なしの判断履歴
- 試運転、定期、手動、RSSのみ、Steam同期の実行状態と安全な結果

APIキー、token、Cookie、Steam ID、記事本文、個別アクセス情報を保存する列は設けていない。

## 安全策

ゲーム本体、任意の出典、任意の価格観測は一つのSQLiteトランザクションで保存する。Steam App ID、HTTP/HTTPS URL、日本円、日付、価格、割引率、状態値、文字数を保存前に検査する。候補点は承認済みの35・25・15・15・10点を超えられない。

メディアやApifyからゲーム情報だけを更新しても、別のSteam同期で確認した所有・ウィッシュリスト状態を消さない。収集実行は開始状態から一度だけ完了でき、二重完了を停止する。

## 管理画面

「リリース・セール情報」でゲーム件数、有効候補、未確認、情報源、価格履歴、最終収集、候補一覧、候補説明を確認できる。AI編集部そのものはPhase Kで実装するが、Phase Jでは固定採点を補足する説明の生成と保存までを共通基盤へ追加した。

## 認証前の収集準備

RSS 2.0とAtomから見出し、URL、日時、本文ではない短い要約だけを最大30件読み取り、HTMLを除去してSteam App IDを抽出できる。入力は2MBで停止する。Steam日本向け公開応答からタイトル、日本語対応、シングルプレイ、発売日、開発・販売元、日本円価格を検査済みの共通形式へ変換できる。手動試運転は最大10件、週次収集はSteam新作10件・セール10件の最大20件である。

4Gamerは公式RSS一覧と利用案内を確認済みである。AUTOMATONとGame*Sparkは正式な取得方法を確定するまで接続しない。管理画面にはApifyとSteam所有情報の設定有無だけを表示し、値は表示・DB保存・ログ出力しない。

2026-08-15に `fetch_cat/steam-store-games-scraper` をPortal 2、Stardew Valley、ELDEN RINGの固定3件で手動試験した。3件とも成功し、日本円価格、基本情報、シングルプレイヤーカテゴリを取得でき、費用は0.005米ドルだった。日本語対応、レビュー、セール終了日時は不足したため、このActorだけで確定せずSteam日本向け公開情報で補完する。Apify ConsoleのDatasetプレビューには `clean` の型不整合があったが、JSON出力は正常で秘密情報を含まなかった。

採用Actorを固定し、トークンをURLではなくBearerヘッダーで送る固定3件のAPI接続確認を管理画面へ追加した。応答は5MB、対象は3件、正式試運転は10件で停止する。スクリーンショット、DLC、本文相当の説明は要求しない。再実行は24時間停止する。

## 最大10件の候補試運転

Steamの日本向け公開一覧から新作5件とセール5件をSteam App IDで重複排除して取得し、Apify ActorとSteam日本向け詳細情報で補足する処理を管理画面へ追加した。最大10件を超えず、ユーザーが「最大10件で候補試運転」を押した場合だけ外部接続する。固定3件の接続確認は正式試運転の24時間制限に含めず、正式試運転同士だけを24時間停止する。

候補は日本語対応、シングルプレイ、ホラー、Steam評価、2万円の例外予算、新作期間、20%以上の通常セール条件で分類する。確認材料が不足する作品は除外せず「要確認」へ分離する。採点は承認済みの100点配分内で行い、候補・要確認・除外と理由を同じ一覧で確認できる。試運転は記事作成、購入、公開、SNS投稿を行わない。

候補一覧から「プレイ候補」「記事候補」「保留」「興味なし」を記録できる。判断は履歴として追記し、最新判断を一覧へ表示する。Steam所有情報の次工程に備え、APIキーとSteam ID64をユーザー環境変数へ登録する `admin/set-steam-credentials.cmd` を追加した。値は画面、DB、ログ、リポジトリへ保存しない。

初回の実データ試運転では、Steam appdetailsの日本円価格が100倍の整数で返る仕様を通常の円として扱い、2万円超と誤判定した。円へ変換する処理を追加し、実行前スナップショットを作成したうえで、この試運転に属する価格9件と該当候補7件だけを補正した。補正後のDB整合性検査は成功している。

## 保留事項

- 日次・月次処理の直前に、使用中のDBをSQLite標準機能で `backup-source/admin/admin.sqlite3` へ複製する。作成前後の整合性検査、原子的な置換、復元確認用フォルダへの復元、稼働中DBへの直接復元拒否をテストした
- 実際の暗号化Google Driveバックアップを動かし、Phase JのDB複製が含まれることを確認する作業は未実施
- 4Gamerは公式RSSへ接続済み。AUTOMATONとGame*Sparkは公式取得口が確認できるまで接続しない
- Steam所有ゲーム同期は実環境で165件の反映を確認済み。認証情報の値は引き続き画面、DB、ログ、Gitへ保存しない
- ウィッシュリストは正式な取得方法を確認できていないため、非公式手段では接続しない
- 実際の週次自動実行結果と4週間後の候補品質見直し

Steam公式の `IPlayerService/GetOwnedGames` を使い、所有App IDと名称だけを取得して一つのトランザクションで反映する。週次処理前の同期に加え、管理画面から所有ゲームだけを明示的に同期できる。APIキーはURL、画面、DB、ログへ含めず、プレイ時間やフレンド情報も保存しない。現在の候補収集、固定採点、候補判断はSteam認証情報なしでも継続利用できる。

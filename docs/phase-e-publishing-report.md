# Phase E 校正・プレビュー・公開 実装報告

作成日: 2026-08-09

状態: 実装・ローカル検証完了

## 実装内容

- Geminiによる構造化校正と、本文を自動変更しない結果表示
- 指摘ごとの採用・見送り記録
- 現在の原稿ハッシュと校正対象ハッシュの照合
- 一時contentを使うHugoプレビュー
- 必須項目、秘密情報、画像、内部リンク、Hugo本番ビルド、生成HTMLの公開前チェック
- 記事ハッシュへ結び付けた15分間有効・一回限りの承認
- 対象slug入力を必要とする最終確認
- 正本と公開コピーだけのstage・commit・push
- GitHub Pages runと公開URL HTTP 200の確認

## 安全策

- 校正結果は `var/admin/reviews/` に保存し、記事bundleと公開対象へ入れない。
- AI入力に秘密情報らしい値があれば送信前に停止する。
- AI出力は構造と危険なHTMLを検査し、コマンドとして実行しない。
- プレビューと公開前チェックは一時コピーを使い、正本を変更しない。
- 既存stage、公開コピーの未コミット変更、対象外stage、ハッシュ変更、校正不一致、承認不足で停止する。
- commit前の失敗は公開コピーを元へ戻す。commit後にpushが失敗した場合は、復旧可能なローカルcommitとして明示する。
- テストから実AI、GitHub、Pagesを呼ばない。

## 検証

- fake AI校正で本文が変わらないこと
- 校正レポートが記事bundleへ入らないこと
- 指摘の採否が本文を変更しないこと
- 原稿変更で古い校正と承認が無効になること
- Hugo失敗時に原稿が維持されること
- 承認なしでGit・外部通信が呼ばれないこと
- stage混入時にcommit・pushしないこと
- 実Hugoによる一時記事のプレビューと公開前チェック成功

実装作業中に実記事のAI校正、commit、push、Pages公開は実行していない。

## 管理画面デザイン調整

個人利用に合わせてPhase表示、localhost表示、常時表示の補足説明、大きな入力検査枠を削減した。フォントはPC内のNoto Sans JPを使用し、角丸と影をほぼなくした直線的な外観、小さいボタン、狭い余白へ変更した。安全停止メッセージと公開の最終確認は省略しない。

投稿の最終確認画面と投稿完了画面はHTMLとして返すよう明示し、HTMLコードが文字列のまま表示される問題を修正した。再発防止として最終確認画面のContent-TypeとHTML先頭をテストする。

## 現在の運用調整

- slugを `YYYYMMDD-NNN` の日別連番で自動作成する。
- 記事一覧にタイトル・slug検索を追加する。
- 一覧の「削除」は論理削除とし、正本を保持して「設定・履歴」から復元できる。
- 記事一覧を「下書き」「公開済」のタブ切替にし、移行前原稿の確認入口を一覧から外す。
- AI校正は停止・非表示とし、公開前チェックの必須条件から一旦外す。過去の校正記録は保持する。
- 移行前の外部テスト原稿3件はユーザー承認後にWindowsのごみ箱へ移動した。管理画面の記事と公開用記事は削除していない。
- 編集画面上部を保存済みタイトルへ連動し、画像欄へサムネイル、Markdown文字列、コピーボタン、アップロード欄の余白を追加した。
- 公開済み記事の保存を「公開記事の更新下書き」として識別し、再投稿まで旧公開版を維持する表示を追加した。本文操作を右上へ移し、下書きのアーカイブ欄を非表示にした。
- 未確定自動保存を公開前に停止し、差分0件を正しく案内するよう修正した。commit前の投稿失敗は更新下書きへ戻し、旧公開版がある記事を公開済みタブにも残す。

## 2. 実装した内容

### 本文を書き換えない校正基盤

`scripts/review_article.py` と `review.ps1` を追加した。指定した1記事の `index.md` を読み取り、校正前、AI応答取得後、保存直前、保存後にSHA-256を比較する。1回でも変化した場合は停止し、新しいレポートを残さない。既存レポートを置き換えた直後に本文変更を検出した場合は、既存レポートを元へ戻す。

スクリプトには本文・画像の書き込み、移動、削除、再圧縮、コマンド実行機能を持たせていない。AIの修正案は厳格な構造化データとして読み、Markdownの `review-report.md` へ変換するだけである。

### AI入力の限定とdry-run

送信対象は次だけである。

- 指定した1記事の許可済みfront matter
- 記事本文
- 記事種別、description、プレイ時間、ネタバレ、提供などの公開情報
- Markdownから抽出した画像ファイル名と代替テキスト

送信しないものは、APIキー、Webhook URL、Git認証情報、Obsidian全体、別記事、過去のレポート、`.git`、`.env`、OSのユーザー情報、ブログ以外の個人メモ、画像本体、`my-blog` である。

`-DryRun` は対象ファイル、ハッシュ、front matter項目、本文文字数、画像参照件数、除外対象を表示する。本文を含む実際の構造化入力は `-PrintRequest` で人が確認できる。どちらも外部送信しない。

### 秘密情報検査

入力前と保存前に、GitHub token、OpenAIやGoogle等のAPIキー形式、Discord Webhook URL、秘密鍵、Bearer token、認証Cookie、秘密情報らしい環境変数代入、メールアドレスを検査する。検出時は値を表示せず、「種類」と「行」だけを表示して停止する。

公開する意図があるメールアドレスも安全側で停止する。必要になった場合は、公開連絡先の明示方法をユーザーと決めてから例外規則を追加する。

### レポート形式と安全な保存

レポートには、対象記事、SHA-256、実行日時、方法・ツール、総合結果、指摘件数、6分類、重要度、該当箇所、修正理由、修正案、ユーザー確認項目を記録する。指摘のない分類は「指摘なし」と明記する。

AI応答は `data/editorial/review-response-template.json` と同じ6分類のJSONだけを許可する。分類不足、重複、不明な重要度、空の必須項目、危険なHTMLやスクリプト、秘密情報の疑いがある出力は保存しない。AI出力をコマンドとして実行しない。

レポートは記事フォルダ内の一時ファイルへ完全に書き、同期後に `review-report.md` だけを置き換える。失敗時は途中ファイルを残さない。同じ原稿・同じ方法・同じ応答は既存結果を再利用し、実行日時だけの差分を増やさない。

既存レポートと異なる結果は自動上書きしない。ユーザーが内容を確認し、`-Replace` を明示した場合だけ置き換える。現行運用は記事ごとに1ファイルとし、複数世代の履歴保存は将来必要になった場合に再検討する。

### プレビュー・公開との連携

`preview.ps1` と `publish.ps1` の既存処理へ、レポートの安全性と鮮度確認だけを追加した。AI校正そのものを `Ctrl+Alt+V` へ組み込んでいない。

- 最新レポート: 通常表示
- レポートなし: 警告、続行可能
- 本文更新後の古いレポート: 警告、続行可能
- レポート内に秘密情報の疑い: 停止
- 壊れたレポートまたは不正ハッシュ: 停止

既存の一時領域同期、`review-report.md` 除外、`draft: false`、対象記事限定stage・commit、承認後push、Actions・公開URL確認は変更していない。

### Gemini 3.6 Flash接続

公式 `google-genai` SDKのInteractions APIを使うアダプターを追加した。モデルIDは `gemini-3.6-flash` に固定し、6分類のJSON SchemaをAPIへ指定する。APIキーは `GEMINI_API_KEY` 環境変数だけから読み、キー未設定時は通信前に停止する。

Google検索等のツールは渡さず、会話保存は `store: false` とする。通信失敗時はキー、応答全文、SDK例外の詳細をログへ表示せず、本文と既存レポートを維持する。

実通信専用の `scripts/gemini_smoke_test.py` は、短い架空原稿だけを一時フォルダから1回送信する。Obsidian原稿を使わず、本文ハッシュ不変、6分類レポート、終了時の一時データ削除を確認する。

2026-08-02に `gemini-3.6-flash` へ1回だけ実通信し、成功した。APIキーの値とAI応答全文は表示していない。架空原稿のSHA-256が前後で一致し、6分類を持つ最新レポートとして解析でき、テスト終了後に一時フォルダが残っていないことを確認した。実記事、画像、Obsidian原稿、過去レポートは送信していない。

公式SDK 2.7.0から、Interactions APIは試験的で将来変更される可能性があるという警告が出た。現在の疎通には成功しているが、SDK更新時は呼出形式と構造化出力を再確認する。

Obsidianの4操作を `Ctrl+Alt+V/K/P/L` に統一した。校正実行前に、本文を変更しないこと、既存レポートを置き換えること、本文をGemini無料枠へ送ることを確認画面へ表示する。「はい」の場合だけ別画面で校正する。Claude Code用Cは復活させていない。設定変更前のファイルはWindows一時フォルダへバックアップする。

手動確認用として、Obsidianの `01_blog/phase2-review-demo/` に `draft: true`、`test_content: true` の架空記事と空の `images/` を新規作成した。既存記事は変更していない。記事には誤字、矛盾、曖昧表現、未確認の事実、構成不足を意図的に含め、初回の `review-report.md` はユーザーの校正操作で生成された。

## 3. 警告と停止条件

警告に留めるもの:

- レポートがない
- 原稿更新後でレポートが古い
- 誤字、日本語、読みやすさ、事実確認、SEO、構成の提案が残っている
- AIサービスが利用できない

公開または校正を停止するもの:

- 校正中に `index.md` が1バイトでも変化した
- 対象記事を一意に特定できない
- 入力または出力に秘密情報の疑いがある
- AI応答または既存レポートを安全に解析できない
- レポートの安全な保存に失敗した
- `review-report.md` が公開用contentへ入った
- Phase 1のfront matter、画像、内部リンク、下書き、生成HTML、Hugoビルド検査が失敗した

AI校正は任意の品質支援であり、サービス停止やレポートなしだけでは公開を止めない。これは既存仕様の「文章上の指摘は提案」と一致する。

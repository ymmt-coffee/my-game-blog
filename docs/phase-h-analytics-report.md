# Phase H アクセス解析実装報告

作成日: 2026-08-11
状態: 現在必要な範囲は完了、有料API連携は保留

## 実装した範囲

- 集計済みCSVを管理画面から取り込める。
- 7日、30日、90日の閲覧数と延べ訪問者数を表示する。
- 同じ長さの直前期間と増減を比較する。
- 日別閲覧数、よく読まれたページ、簡単な確認候補を表示する。
- CSVひな形を管理画面から取得できる。
- 取込履歴をSQLiteへ記録する。

## CSV形式

必須列は `date,path,views,visitors` である。日付は `YYYY-MM-DD`、pathはクエリ文字列を含まない `/` 始まりの公開ページパスとする。

同じデータ元、日付、ページを再度取り込んだ場合は新しい値へ置き換える。追加加算しないため、同じCSVの再取込で数値が倍にならない。

## 安全・プライバシー

- IPアドレス、Cookie、ユーザーエージェント、参照元の生データを保存しない。
- CSVはUTF-8、2MB以下、10,000行以下に制限する。
- 不正な日付、負数、重複、クエリ文字列を検出した場合は全体を取り込まず停止する。
- SQLiteには日別・ページ別の集計値だけを保存する。
- テストでは外部サービスへ接続しない。

## 保留事項

2026-08-12にUmami Cloudを採用し、FRAMING専用Websiteを追加した。公開サイトにはFRAMING用Website IDを設定し、`ymmt-coffee.github.io` の `/my-game-blog/` 配下だけを送信対象とする。検索パラメーターとハッシュを除外し、Do Not Trackを尊重する。

自己アクセス除外はCookieではなくブラウザのlocalStorageを使う。公開後に次のURLを自分が利用するブラウザで一度開く。

`https://ymmt-coffee.github.io/my-game-blog/?umami_ignore_self=1`

除外を解除する場合は次を開く。

`https://ymmt-coffee.github.io/my-game-blog/?umami_ignore_self=0`

除外用パラメーターは計測コードの実行前にURLから取り除く。別ブラウザや別端末では、それぞれ設定が必要である。

2026-08-12に公開サイトからUmami Cloudへ実データが記録されることを確認した。自己アクセスを除外したブラウザとは別の環境からアクセスし、`/my-game-blog/` の表示と訪問者が計上された。

Aboutページには、利用目的、Umami Analyticsの利用、Cookieを使わないこと、匿名の統計情報として記録する項目を追記した。

Umami CloudのHobbyプランではダッシュボードを日常確認に使い、API自動取得のためだけには有料プランへ変更しない。ローカル管理画面の既存CSV取込は、必要になった場合の補助手段として残す。

Umamiの実エクスポートで `website_event.csv` の形式を確認し、管理画面からそのまま取り込める変換処理を追加した。ページ表示だけを日本時間の日付と公開パスで集計し、表示数とページ別・日別のユニークセッション数へ変換する。サイトの `/my-game-blog/` 接頭辞は管理画面内の `/` 基準へ正規化する。個別のセッションID、訪問ID、端末、地域、参照元、パフォーマンス値はSQLiteへ保存しない。API連携は、将来有料プランを利用する別の理由が生じた場合にだけ再検討する。

毎月1日20:00を「前月アクセス解析レビュー」とし、管理画面の月・週カレンダーへ定期表示する。予定からアクセス解析画面へ移動し、Umami Cloudから前月分を手動でエクスポートして `website_event.csv` を取り込む。よく読まれた記事、伸びたカテゴリー、次に書く候補の方向性を確認するが、記事の自動選定・自動生成・自動公開は行わない。

## 将来必要になった場合の作業

現在は次の作業を必須としない。アクセス数が蓄積し、Umami画面だけでは管理しにくくなった場合に次の順序で再開する。

1. 記事パスと記事タイトルを紐付け、公開後7日・30日の比較を追加する。
2. カテゴリー別の傾向が必要になった場合に集計表示を追加する。
3. APIが必要になった場合だけプラン費用と効果を再評価し、認証情報をGit管理外へ置いて実装する。

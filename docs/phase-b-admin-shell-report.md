# Phase B ローカル管理画面の土台 実装報告

実施日: 2026-08-09
状態: 実装完了・ローカル検証済み

## 結論

PC内だけで動くローカル管理画面の土台を実装した。左メニューから各予定画面へ移動でき、未実装機能は「準備中」と表示する。設定・履歴画面では接続範囲、状態DB、記事操作の状態、安全な起動履歴を確認できる。

記事編集、画像操作、校正、公開、原稿移行は実装しておらず、既存記事やObsidian運用へ影響しない。

## 実装内容

- FastAPIによるローカルWebアプリ
- `127.0.0.1:8765` 固定の起動
- デスクトップアイコンからの起動と既定ブラウザ自動表示
- デスクトップ起動はPowerShell 7を使用し、Windows PowerShell 5.1によるUTF-8文字化けを回避
- 許可Hostを `127.0.0.1` と `localhost` に限定
- 同時に複数起動しないプロセスロック
- 固定左メニューとレスポンシブ表示
- ホーム画面
- 記事管理、スケジュール、AI編集部、リリース・セール、SNS分析、アクセス解析の準備中画面
- 設定・履歴画面
- SQLiteの初期化、schema migration、破損時の停止
- Git管理外の `var/admin/admin.sqlite3` への安全な起動履歴
- ヘルスチェック

## 起動と終了

デスクトップの「ゲームブログ管理」アイコンを開くと、管理画面を起動して既定ブラウザへ自動表示する。すでに起動中なら二重起動せず、ブラウザだけを表示する。

手動の場合はプロジェクトルートで次を実行する。

```powershell
.\admin\start-admin.ps1
```

ブラウザで `http://127.0.0.1:8765/` を開く。終了は起動画面で `Ctrl+C`。

## 安全策

- 起動コードから接続先やポートを自由入力できないようにした
- API仕様画面は公開しない
- CORSを有効にしない
- Host偽装を拒否する
- 状態DBに秘密情報や記事本文を保存しない
- DB破損を検出した場合は自動上書きせず停止する
- ログは安全な定型メッセージに限定する
- `var/` はGit、Hugo公開、バックアップの公開対象から除外される
- 記事や公開処理へ書き込むAPIはまだ設けない

## 依存パッケージ

`requirements.txt` にFastAPIとUvicornを追加した。React、Node.js、外部DB、クラウドサービスは追加していない。追加の外部サービス費用はない。

## テスト

Phase Bテストでは次を確認する。

- ホームと全メニュー画面の表示
- 準備中表示
- localhost限定を示すhealth応答
- 未許可Hostの拒否
- DB schemaと安全な起動履歴
- 破損DBを上書きしない停止
- bind先が `127.0.0.1` に固定されていること

これに加えて、記事関連25件、バックアップ関連26件、Hugo本番相当ビルドを回帰確認する。

## 外部変更

- Python環境へFastAPIとUvicornをインストールした
- Windowsタスク、Obsidian設定、GitHub、公開ブログは変更していない
- commit、push、公開は行っていない
